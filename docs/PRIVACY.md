# Privacy-Conscious Analytics

Collect the minimum fields required by the analytical question. More data increases access, retention, breach, and misuse risks; it does not automatically produce better answers.

The tutorial fixture contains fictional event, session, and synthetic-member identifiers plus limited technical context. It deliberately excludes names, addresses, email addresses, government identifiers, account numbers, passwords, authentication tokens, and actual financial information.

Operational data exists to execute a banking process and may be sensitive or authoritative. Analytics data exists to answer defined questions and should usually be minimized, transformed, access-controlled, and retained under its own policy. A synthetic identifier in this book is safe teaching data; in a real system, a pseudonymous identifier may still be linkable and must be governed accordingly.


## Part III collection boundary

Navigation uses normalized page/feature names and explicit transitions. Search stores only an allowlisted synthetic `search_category`, never free-form query text. Arrival context uses fictional normalized sources, referrals, landing pages, and campaign tags. These fields support aggregate digital-experience questions without names, contact details, account identifiers, financial values, or complete advertising-exposure histories.
